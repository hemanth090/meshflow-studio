# MeshFlow Studio: Architecture

This document explains how the shipped plugin works at runtime: how the bundle is built, what each
module owns, how a composition is rendered and exported, how the plugin attaches to the Harness Web
UI, and how the tests verify all of it.

The build contract in [CONTRACT.md](../CONTRACT.md) is the authoritative spec for module APIs;
this document is the map of the implementation. Read `CONTRACT.md` before changing a public member.

---

## 1. Design constraints

MeshFlow Studio is a **client-side DSH Web UI plugin**: a single main-panel design studio plus a
sidebar panel icon and a composer launcher. There is no host half beyond an empty `apply()` in
`index.js`, no server component, no tool and no network access.

Four constraints drive almost every decision in the codebase:

1. **One self-contained browser bundle.** The plugin ships as `client.js`, a
   `window.__ModuleLoader__.load({...})` factory. There is no bundler, no JSX compiler, no
   TypeScript and no npm runtime dependency - only `react`, which the Harness provides.
2. **Small, auditable surface.** Chrome uses Harness theme tokens, all copy goes through the locale
   service, and browser APIs (canvas, clipboard, download anchors, `localStorage`) are touched only
   inside functions/effects and always behind feature detection.
3. **Deterministic artwork.** A composition is plain JSON; the same state renders the same pixels and
   produces the same CSS/JSON export. Grain uses a seeded PRNG, randomization is seed-deterministic.
4. **Defensive by default.** A hostile or broken canvas/clipboard/localStorage must never take the
   panel down: every public export helper resolves to `false`/`null` instead of throwing.

## 2. Build model and bundle format

`build.mjs` concatenates the fragments in a fixed order and writes the generated `client.js`
(≈8,500 lines / ≈249 KB at v1.0.0):

```js
/**
 * MeshFlow Studio - generated by build.mjs. Do not edit by hand.
 * Edit src/*.js and rebuild instead.
 */
window.__ModuleLoader__.load({
  id: '@local/meshflow-studio',
  factory(require) {
    const React = require('react');
    const h = React.createElement;

    /* ---- src/00-prelude.js ---- */
    …
    /* ---- src/60-register.js ---- */
    …

    return {
      inject: ['slots', 'locale'],
      apply(ctx) { /* mount */ },
    };
  },
});
```

- Running the bundle only **registers a lazy factory**; the factory body is not evaluated until the
  Harness materialises the plugin. This keeps module-scope side effects out of page load.
- The factory body provides `React`, `h` and `require` to every fragment. Fragments are plain
  scripts - the build rejects any fragment containing a top-level `import`/`export`.
- `build.mjs` also fails loudly when a fragment in `ORDER` is missing, strips trailing whitespace per
  fragment, and prints the written line/byte counts.

**Generated-bundle rule:** never edit `client.js` by hand. Edit `src/`, run `node build.mjs`, and
commit the rebuilt bundle in the same change. CI enforces this with `node build.mjs` followed by
`git diff --exit-code -- client.js`.

Bundle plumbing around the generated file:

| File | Role |
|---|---|
| `package.json` | `@local/meshflow-studio`, `private: true`, ESM (`type: module`), exports for `./client`, `./locale/*.json`, `./icon`, and the `dsh.client` manifest (platform `web`, `immediately: true`, injects `@deepseek-ai/dsh-client-ui-conversation`). |
| `cordis.patch.yml` | Loader patch that inserts the `@local/meshflow-studio` bundle row into the profile. |
| `index.js` | Host half: an intentionally empty `apply()`; the plugin contributes no host services/tools. |
| `icon.svg` | Panel artwork referenced by the package exports. |
| `locale/en.json`, `locale/zh.json` | Host-side locale metadata (`meta.title`, `meta.description`); the runtime dictionaries live in the fragments. |

## 3. Module graph

Fragments are evaluated top-to-bottom inside the factory, so **order is a dependency**: a module may
reference members defined above it at evaluation time (lazy references inside functions are always
fine). Every module attaches exactly one member to the shared `MF` namespace.

| # | Fragment | Attaches | Responsibility |
|---|---|---|---|
| 00 | `00-prelude.js` | `MF`, `MF.util`, `MF.cssAll` | Namespace identity (`MF.ID`, `MF.VERSION`), `strings: {}` container, pure utilities (`clamp`, `lerp`, `round`, `trim`, `uid`, `clone`, `mulberry32`, `pick`, `shuffle`), and the `cssAll()` assembler used by the studio. |
| 10 | `10-model.js` | `MF.model` (+ `MF.strings.model`) | Pure composition domain: 8 aspects, `LIMITS`, mix modes, grain blends, 8 palettes, 16 presets, immutable state helpers (`createState`, `normalize`, `addPoint`, `patchPoint`, `applyPreset`, `randomize`, `recolor`), JSON (de)serialisation, colour maths, and deterministic `toCSS` / filename generation. **No DOM.** |
| 20 | `20-engine.js` | `MF.engine` | Canvas renderer. `PIPELINE`, mapping helpers, `render(canvas, state, options)`, `renderToCanvas`, `exportCanvas`, `toDataURL`. Owns the offscreen buffer/tile caches and the seven-stage draw pipeline. |
| 25 | `25-exporter.js` | `MF.exporter` | Browser output actions: PNG download, copy PNG/CSS/JSON, download CSS/JSON. Async, never throws, DOM only during a call, temporary nodes always removed. |
| 30 | `30-controls.js` | `MF.ui` (+ `MF.strings.ui`) | Presentational React primitives (`Button`, `IconButton`, `Slider`, `Toggle`, `Segmented`, `Select`, `ColorField`, `SwatchRow`, `Section`, `Tabs`, `Row`, `Badge`, `Kbd`, `Icon`) and `MF.ui.css` (`mf-ctl-*`). No application state. |
| 40 | `40-panels.js` | `MF.panels` (+ `MF.strings.panels`) | Studio side panels: `PresetThumb` (canvas preview in an effect), `PresetRail`, `LayerList` and the four-tab `Inspector` (mesh / effects / glass / export) plus `MF.panels.css` (`mf-pnl-*`). Panels are dumb - they receive `state`, `t` and callbacks. |
| 50 | `50-studio.js` | `MF.Studio` (+ `MF.strings.studio`, `MF.studioCss`) | Main panel page: composition state via `useReducer`, undo/redo history, persistence, canvas render loop (rAF + `ResizeObserver`), node dragging with pointer capture, keyboard shortcuts, toast, export wiring, responsive layout and `mf-st-*` styles. |
| 60 | `60-register.js` | locale registration + three slot contributions | Merges dictionaries, registers the `meshflow-studio` locale namespace, contributes `sidebar.panellist`, `main` and `conversation.input.left`, binds `t` to the locale service, and exports the Client plugin object `{ inject, apply }`. |

Why the split: the model and engine stay DOM-free and directly unit-testable, the presentational
layers stay state-free, and only `MF.Studio` + the registration fragment know about the host.

## 4. Shared namespace

```js
MF = {
  ID: 'meshflow-studio',
  VERSION: 1,
  strings: {},              // per-module dictionaries, merged at registration
  util: { clamp, lerp, round, trim, uid, clone, mulberry32, pick, shuffle },
  cssAll() { /* MF.ui.css + MF.panels.css + MF.studioCss */ },
  model, engine, exporter, ui, panels, Studio, studioCss,
};
```

Rules: one member per fragment, never rename or re-shape a `MF.*` member (they are the internal
contract), share helpers through `MF.util` rather than duplicating them, and never touch another
module's DOM or styles.

## 5. Composition state

A composition is a plain, JSON-serialisable object; `MF.model.normalize` is the single source of
truth for defaults and clamping.

```js
{
  version: 1,
  name: 'Untitled mesh',
  aspect: '16:9',                 // MF.model.ASPECTS id
  base: '#0a0a12',
  mix: 'normal',                  // normal | screen | overlay | soft-light | lighter
  points: [                       // 2..12 nodes
    { id: 'p1', x: 0.28, y: 0.32, color: '#6ee7ff', size: 0.62, opacity: 1 },
  ],
  blur: 0,                        // 0..100
  grain: { enabled: true, amount: 0, scale: 34, seed: 7, blend: 'overlay' },
  vignette: { enabled: false, amount: 24, size: 60 },
  glass: {
    enabled: false, x: 0.5, y: 0.5, w: 0.52, h: 0.42, radius: 28,
    blur: 18, opacity: 14, tint: '#ffffff', border: 40, sheen: 30,
  },
  palette: 'aurora',
}
```

- `x`/`y` are fractions of the artboard (0..1, node centre); `size` is a radius factor of the
  artboard's longest side; `opacity` is 0..1. All numeric limits come from `MF.model.LIMITS`.
- Consumers treat state as immutable: they spread to build the next state and call
  `onChange(nextState, coalesce)`. `MF.model.normalize` / `deserialize` run at the edges (restore,
  imports) so the studio never renders an out-of-range composition.
- **History** is a `{ past, future, gesture }` record in `MF.Studio`'s reducer: max 80 snapshots,
  slider changes coalesce within 600 ms, a pointer drag pushes exactly one entry on pointer-down,
  and redo is cleared on a new commit.
- **User presets** are `{ id, name, state, createdAt }`, capped at 24 entries with names trimmed to
  32 characters.

## 6. Render pipeline

`MF.engine.render(canvas, state, options)` normalises the state, sizes the canvas to
`width × height × pixelRatio`, installs a scaled transform so drawing coordinates stay logical, and
runs the stages below in order. It returns `{ width, height }` and **never throws:** a failed stage
leaves the previous frame in place.

`options = { width, height, pixelRatio = 1, draft = false, guides = false }`; `pixelRatio` is
clamped to 0.25–3 and forced to ≤ 1 in `draft` mode.

| # | Stage | What it draws / how |
|---|---|---|
| 1 | **base** | Solid `state.base` fill of the whole artboard. |
| 2 | **blobs** | All point blobs are drawn onto one reusable offscreen layer (cached by size) as radial gradients - point colour at 0 %, same colour at 0 % alpha at 72 %, transparent at 100 % - then the whole layer is composited once with the mapped mix mode (`normal → source-over`, `screen`, `overlay`, `soft-light`, `lighter`). Drawing all blobs on one layer is what makes the mesh blend smoothly instead of stacking colours. |
| 3 | **blur** | `MF.model.blurPx` converts the 0–100 slider into device pixels; `ctx.filter = 'blur(…)'` is feature-detected once. The frame is snapshotted to an offscreen buffer first to avoid self-read artefacts, then drawn back blurred. Browsers without `ctx.filter` skip the stage gracefully. |
| 4 | **vignette** | A radial gradient centred on the artboard: transparent centre (size-controlled) → darkened corners at `amount × 0.92` black. |
| 5 | **grain** | A deterministically generated monochrome noise tile (`mulberry32(seed)`, tile size derived from `grain.scale`) is cached by `seed:size`, turned into a repeating pattern, and composited with `globalAlpha = amount/100` and the mapped blend (`overlay` / `soft-light` / normal). `amount = 0` or a disabled layer is a no-op. |
| 6 | **glass** | Snapshot the current canvas, clip a rounded rect from `glassRect` (centre `x,y`, size `w,h`, clamped radius), draw the snapshot back through `blur(glass.blur)` as the frosted backdrop, fill the tint at `opacity/100`, add a diagonal sheen gradient at `sheen/100`, a 1 px top highlight and a border stroke at `border/100`. |
| 7 | **guides** | Only when `options.guides`: thin crosshair/centre and artboard bounds markers (4 px logical) for layout debugging. |

Every stage resets `filter`, `globalCompositeOperation` and `globalAlpha` in a `finally` block, so a
throwing browser API cannot poison the next frame. Helpers:

- `renderToCanvas(state, options)` → detached canvas (or `null` when the environment cannot create
  one); used for preset thumbnails and export.
- `exportCanvas(state, scale)` → canvas at `dimensionsOf(state) × scale`, longest side capped at
  8192 px; used by PNG export and Copy PNG.
- `toDataURL(state, scale)` → `image/png` data URL (empty string on failure).

In the studio, rendering is scheduled from a `useEffect` on `[state, stageSize, interacting]` inside
`requestAnimationFrame`, with `pixelRatio = min(2, devicePixelRatio)` normally and `1` while
interacting (`draft`). A `ResizeObserver` feeds the stage size; cleanup cancels the pending frame and
disconnects the observer.

## 7. Slots, lifecycle and locale binding

The Client plugin object returned by the factory is:

```js
return {
  inject: ['slots', 'locale'],
  apply(ctx) { … },
};
```

`apply` bails out (with a console error) when the locale service is unavailable; otherwise it runs
registration through `ctx.effect(install, 'meshflow-studio')` when the host supports effects so the
mount is tied to the plugin lifecycle (falling back to a direct install). Each registration step is
individually wrapped in `try/catch`, exactly one disposer is collected per contribution, and dispose
runs in reverse order.

Contributed slots:

| Slot | Key / id | Order | What is mounted |
|---|---|---|---|
| `sidebar.panellist` | id `meshflow-studio` | 20 | `MfPanelIcon` - inline SVG mark (gradient blobs + a sparkle), active ring via `strokeOpacity`; its `label` is resolved from the locale service. |
| `main` | key `meshflow-studio` | default | `MfStudioPanel` - the studio page. |
| `conversation.input.left` | id `meshflow-studio-launcher` | 30 | `MfStudioLauncher` - compact pill button (hover/focus states from theme tokens) that calls `layout.selectPanel('meshflow-studio')`. |

**Locale-bound wrapper.** `MfStudioPanel` subscribes to the locale service with
`React.useSyncExternalStore(locale.subscribe, () => locale.getSnapshot().revision)` so a language
switch in Harness Settings re-renders the whole studio. It renders `h(Studio, { t })` where `t` is
produced by `mfTranslate(locale)`:

```js
const bind = locale.bind('meshflow-studio');
return function t(key) {
  try { const value = bind(key); if (typeof value === 'string' && value) return value; }
  catch { /* fall through */ }
  return key;   // never render "undefined"
};
```

The launcher and panel-icon label use the same bound translator. The plugin never creates a second
React root, never portals, and never renders outside the slot host's tree.

## 8. Internationalisation

Every visible string flows through `t(key)`. Each fragment owns its dictionary group:

```js
MF.strings.panels = {
  en: { 'panels.presets': 'Presets', … },
  zh: { 'panels.presets': '预设', … },
};
```

- **Groups:** `model` (45 keys), `ui` (21), `panels` (79), `studio` (28) and `register` (3) -
  176 keys per locale at v1.0.0, with identical `en`/`zh` key sets and non-empty values (checked by
  the model tests and the integration test).
- **Merge:** `mfMergeDictionaries(localeId)` iterates `Object.keys(MF.strings)` (module order) and
  keeps the **first** definition of each key, so an earlier module wins on an accidental collision.
  The merged object is registered once per locale through
  `locale.register('meshflow-studio', 'en' | 'zh', merged)`.
- **Standards:** keys are prefixed by the owning module (`model.`, `ui.`, `panels.`, `studio.`,
  `mesh.`, `effects.`, `glass.`, `export.`), stay under 40 characters, and must exist in both
  locales. Shared keys (`mesh.*`, `effects.*`, `glass.*`, `export.*`) are owned by the UI/panels
  modules and reused by the studio - never redefined with different text.

## 9. Persistence

| Key | Contents | Behaviour |
|---|---|---|
| `meshflow-studio.state.v2` | Current composition, serialised by `MF.model.serialize` (versioned envelope). | Written debounced by 500 ms after state changes; read on mount via `MF.model.deserialize` + `normalize`; corrupt/foreign values are ignored. |
| `meshflow-studio.presets.v1` | User presets: `{ id, name, state, createdAt }[]`. | Written immediately on change (small data); invalid entries filtered and normalised on load; capped at 24. |

Both writes are wrapped in `try/catch`, so quota errors, private-mode storage and disabled
`localStorage` leave the studio fully functional in memory. Clearing the keys resets the studio.

## 10. Export paths

Exports are wired in `MF.Studio` (panels only render buttons) and implemented in `MF.exporter`.
Every helper is `async`, guards each optional browser API, and resolves `false`/`null` on failure
rather than throwing.

| Action | Implementation | Fallback / failure mode |
|---|---|---|
| **Download PNG** (1× / 2× / 4×) | `MF.engine.exportCanvas(state, scale)` → `canvas.toDataURL('image/png')` → temporary `<a download>` click. | No canvas/URL support → `null`; the anchor is removed synchronously. |
| **Copy PNG** | `exportCanvas` → `canvas.toBlob('image/png')` → `navigator.clipboard.write([new ClipboardItem({'image/png': blob})])`. | Missing clipboard/`ClipboardItem`/`toBlob`, permission errors → `false`. |
| **Copy CSS** | `MF.model.toCSS(state)` → `copyText`. | `navigator.clipboard.writeText`; falls back to a hidden textarea + `document.execCommand('copy')`; textarea always removed. |
| **Copy JSON** | `MF.model.toJSON(state)` (pretty envelope) → `copyText`. | Same clipboard fallback as Copy CSS. |
| **Download CSS** | `MF.model.toCSS(state)` → `Blob` + `URL.createObjectURL` → temporary anchor → revoke URL. | No `Blob`/object URL → `false`. |
| **Download JSON** | `MF.model.toJSON(state)` → same blob/anchor path. | Same. |

PNG filenames come from `MF.model.filename(state, scale)` - a slug of the composition name/preset
plus output dimensions, e.g. `meshflow-aurora-veil-3200x1800.png`. CSS/JSON reuse that base name with
`.css` / `.json`. Large exports are capped at 8192 px on the longest side by the engine.

## 11. Styling and theming

- Three stylesheet strings live beside their components: `MF.ui.css` (`mf-ctl-*` primitives),
  `MF.panels.css` (`mf-pnl-*` panels) and `MF.studioCss` (`mf-st-*` page layout). `MF.cssAll()`
  concatenates them and the studio injects the result **once**, at the root of the panel, as a single
  `<style dangerouslySetInnerHTML>` element.
- **Chrome colours are theme tokens only:** `--dsw-alias-bg-base`, `-bg-layer-1/2`, `-bg-overlay`,
  `-border-l1/l2`, `-brand-primary`, `-label-primary/secondary`, the state colours and
  `--dsw-specific-sidebar-fill`. Literal colours appear only in artwork (canvas, preset thumbnails,
  swatches, gradient values, the sidebar mark) and in values that belong to the saved composition
  (glass tint is user data, not chrome).
- The layout is a three-column grid (`236px minmax(0,1fr) 296px`) that collapses to a single column
  below ~1080 px; the artboard keeps its aspect ratio inside the available stage. Animations respect
  `@media (prefers-reduced-motion)`.

## 12. Test strategy

All tests are plain `node:test` with `node:vm`; there is no browser runner and no test dependency.

| File | Tests | Strategy |
|---|---|---|
| `test/model.test.mjs` | 28 | Loads `00-prelude.js` + `10-model.js` in a VM context seeded with the prelude and asserts aspects/limits, normalisation of garbage, deterministic `randomize`, all 16 presets valid and distinct, colour round-trips, CSS/JSON codegen (no `undefined`), filename/`blurPx`/tile-size ranges, serialise→deserialise round-trip and `en`/`zh` coverage for the model dictionary. |
| `test/engine.test.mjs` | 17 | Loads model + engine in a VM with a minimal canvas/2D-context stub: pipeline order, mix/blend mappings, `glassRect` clamping, cache reuse, deterministic grain per seed, disabled stages skipped, guides only when requested, missing/throwing `ctx.filter`, toxic contexts, `renderToCanvas`/`exportCanvas`/`toDataURL` guards and the 8192 px export cap. |
| `test/exporter.test.mjs` | 18 | Loads model + engine + exporter in a VM and stubs clipboard/DOM APIs to cover every helper: no-throw/no-DOM guards, `clipboard.writeText` success, hidden-textarea `execCommand` fallback + cleanup, `ClipboardItem` PNG path, temporary anchor download + filename, Blob/object-URL CSS/JSON downloads with revocation, and the `false`/`null` failure paths. |
| `test/integration.test.mjs` | 6 | Reads the **generated** `client.js`, runs it in a VM with a minimal React stub, materialises the lazy factory, and drives `apply()` against fake `locale`, `slots` and `layout` services. Verifies the plugin shape, merged `en`/`zh` dictionaries (same key count, every value non-empty), and all three slot contributions - before anything is installed in a profile. |

**69 tests total.** Run them with:

```sh
node build.mjs                 # required for the integration test
node --check client.js
node --test test/*.mjs
```

CI (`.github/workflows/ci.yml`) runs on Ubuntu with Node 20 and 22: `node --check client.js`,
`node build.mjs`, `git diff --exit-code -- client.js` (generated bundle must match sources), then
`node --test test/*.mjs`.

## 13. Failure handling and security posture

- **No network, ever.** There is no `fetch`/XHR/WebSocket call in the bundle, no telemetry and no
  external asset loading (icons are inline SVG, thumbnails are generated locally).
- **Untrusted input is normalised.** Restored compositions and user presets are clamped through
  `MF.model.normalize`/`deserialize` before rendering; invalid points, colours and enum values are
  dropped rather than trusted.
- **Browser APIs are optional.** Canvas creation, `ctx.filter`, `toBlob`, clipboard, `Blob`,
  `URL.createObjectURL` and `localStorage` are all feature-detected; missing capabilities degrade to
  a skipped visual stage or a reported "not available" toast, never an exception.
- **DOM hygiene.** Temporary anchors and textareas are removed in `finally` blocks; window
  listeners, timers, rAF callbacks and observers are cleaned up by their effects; the plugin never
  touches `document.body`, another plugin's DOM or global styles.
- **No `innerHTML`** is used for visible chrome; the only `dangerouslySetInnerHTML` is the plugin's
  own generated CSS `<style>` element.

## 14. Non-goals and known limits

- No server rendering, no multi-user collaboration, no cloud sync.
- No image import or background-image support; the artwork is generated from the composition state.
- No drag-to-reorder of layers (nodes are edited individually), and the node count is capped at 12.
- Blur and the glass frost depend on `ctx.filter`; browsers without it render the stages unblurred
  instead of failing.
- The panel targets desktop-width Harness windows (~640 px and wider); it is not optimised for
  narrow mobile viewports.
